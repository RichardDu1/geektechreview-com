## Introduction

Streaming high-quality video in a home theater setup requires balancing bitrate, codec efficiency, and device compatibility. This guide uses AI-powered tools to automatically select the optimal bitrate and codec for your content and network conditions.

## Prerequisites

- A computer with a modern GPU (NVIDIA or AMD) for hardware encoding
- FFmpeg installed (with libx264, libx265, and NVENC support)
- HandBrake (optional, for GUI-based encoding)
- VMAF (Video Multi-Method Assessment Fusion) for quality scoring
- Sample video files (preferably 4K HDR)

## Step 1: Analyze Your Source Content

Use FFmpeg to probe your video file and extract key parameters:

```bash
ffprobe -v error -show_entries stream=codec_name,width,height,bit_rate -of default=noprint_wrappers=1 input.mkv
```

Note the resolution, frame rate, and current bitrate. For example, a 4K HDR movie might have a bitrate of 50 Mbps.

## Step 2: Set Quality Targets

Define your target quality using VMAF scores. A VMAF of 95+ is considered transparent (indistinguishable from source). For home theater, aim for 93-96.

## Step 3: AI-Powered Bitrate Selection

Use FFmpeg with the `libx264` or `libx265` encoder and the `-crf` (Constant Rate Factor) mode. CRF values range 0-51; lower is better quality. For 4K HDR, start with CRF 18 for x265 and adjust based on VMAF.

Example command for x265 encoding with CRF 18:

```bash
ffmpeg -i input.mkv -c:v libx265 -crf 18 -preset slow -c:a copy output.mkv
```

To automate bitrate selection, use a script that iterates over CRF values and computes VMAF. Here's a Python snippet:

```python
import subprocess
import json

crf_values = [16, 18, 20, 22]
for crf in crf_values:
    subprocess.run(f'ffmpeg -i input.mkv -c:v libx265 -crf {crf} -preset slow -f mp4 -y temp_{crf}.mp4', shell=True)
    vmaf = subprocess.check_output(f'ffmpeg -i temp_{crf}.mp4 -i input.mkv -filter_complex "[0:v]setpts=PTS-STARTPTS[ref];[1:v]setpts=PTS-STARTPTS[main];[main][ref]libvmaf=model_path=vmaf_v0.6.1.json" -f null -', shell=True, stderr=subprocess.STDOUT)
    print(f'CRF {crf}: VMAF score extracted from output')
```

Select the CRF that gives VMAF >= 94 with the lowest bitrate.

## Step 4: Codec Selection Based on Hardware

- **H.264 (libx264)**: Best compatibility with older devices. Use for 1080p streaming.
- **H.265 (libx265)**: Better compression for 4K HDR. Requires hardware decoding on playback devices.
- **AV1 (libaom-av1)**: Best compression but slow encoding. Use for archival or if your playback device supports it.

Use FFmpeg to check encoder availability:

```bash
ffmpeg -encoders | grep -E "libx264|libx265|libaom-av1|nvenc"
```

For hardware encoding (NVIDIA NVENC), use:

```bash
ffmpeg -i input.mkv -c:v h264_nvenc -preset p7 -cq 18 -c:a copy output.mp4
```

## Step 5: Adaptive Bitrate Ladder

Create multiple renditions for adaptive streaming (HLS or DASH). Use AI to predict bitrate ladders based on content complexity. Tools like Bitmovin's Per-Title Encoding or AWS Elemental MediaConvert offer AI-driven ladders, but for DIY, use a script:

```bash
# Example: 4K, 1080p, 720p renditions
ffmpeg -i input.mkv -filter_complex "[0:v]split=3[v1][v2][v3];[v1]scale=3840:2160[v1out];[v2]scale=1920:1080[v2out];[v3]scale=1280:720[v3out]" -map "[v1out]" -c:v libx265 -crf 18 -preset slow -map 0:a -c:a copy output_4k.mkv -map "[v2out]" -c:v libx265 -crf 20 -preset slow -map 0:a -c:a copy output_1080p.mkv -map "[v3out]" -c:v libx265 -crf 22 -preset slow -map 0:a -c:a copy output_720p.mkv
```

## Step 6: Validate with Real-World Testing

Stream the encoded files to your home theater setup (e.g., via Plex or Kodi). Check for buffering, audio sync, and visual artifacts. Use VMAF to confirm quality.

## Conclusion

By combining FFmpeg, VMAF, and a bit of scripting, you can automate the selection of optimal bitrate and codec for your home theater streaming. This workflow ensures the best video quality without wasting bandwidth.
